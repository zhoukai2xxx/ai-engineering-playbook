# 出力契約：詳細設計

AI に「詳細設計を書いて」と依頼するときは、本ファイルの構成を厳守させる。章の省略は禁止。内容がない章は「未定」と理由を書く。

受け入れは `../acceptance-checklists/design-checklist.md` を使う。

```markdown
# （プロジェクト名）詳細設計

## 1. 機能概要
（対象機能、対象ユーザー、この設計の範囲）

## 2. 画面構成
（画面一覧、パス、所属モジュール、権限）

## 3. 状態遷移
（面接ステータスなど。図または矢印）

## 4. API 一覧
| メソッド | パス | 用途 | 権限 |

## 5. データ項目説明
（画面/API と DB カラムの対応）

## 6. 権限制御
（役割 × 機能のマトリクス）

## 7. 例外処理
（エラー、空データ、重複、権限不足）

## 8. 未決事項
- [ ]
```
